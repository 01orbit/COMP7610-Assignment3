\sect{01}{System overview and baseline requirements}
The project combines an OpenZeppelin ERC-20 club-points token (CPT, 18 decimals) with an ERC-721 commemorative collection (Campus-Memo). Deployment creates exactly 1,000 CPT in the CPT contract treasury. Only club administrators may mint or distribute points. NFT issuance is capped at ten; each issuance burns 100 CPT from the issuing administrator. Members receive NFTs, while owners can subsequently transfer or sell them.

\sect{02}{Additional functions and design decisions}
{\small
\begin{tabularx}{\linewidth}{@{}>{\raggedright\arraybackslash\bfseries}p{32mm}X@{}}
Membership and welcome & \code{applyForMembership} records an application; administrator-only \code{approveMembership} grants membership and transfers 5 CPT from the treasury.\\
Voluntary withdrawal & \code{withdrawFromClub} burns the member's entire current CPT balance and revokes membership. Existing NFTs remain with their owner.\\
Administrative burn & \code{adminBurnPoints} destroys a specified user balance amount without allowance; both the balance and total supply decrease.\\
Treasury recovery & \code{adminRecoverPoints} returns user CPT to the treasury without allowance. Supply, membership and NFT ownership remain unchanged.\\
CPT user actions & Standard \code{transfer}, \code{approve} and \code{transferFrom} support direct or delegated transfers, including after withdrawal. Holders can also use \code{burn} or approve \code{burnFrom}.\\
Controlled NFT issuance & \code{mintMemo(member)} checks CPT's current administrator role and the recipient's membership. The administrator approves and pays 100 CPT; the recipient is not charged. Roles can be granted or revoked through AccessControl.\\
NFT transfers and sales & Standard ERC-721 transfers and owner-approved delegation (\code{approve} / \code{setApprovalForAll}) remain available. \code{listMemo} escrows an NFT; \code{cancelMemoListing} returns it; \code{buyMemo} transfers approved CPT to the seller and the NFT to the buyer. Former members may still trade.\\
Stable metadata & \code{tokenURI(id)} generates Base64 JSON on-chain with a numbered name and Edition attribute. One fixed GitHub image is shared; transfers and withdrawal do not alter metadata. No NFT burn or administrator recovery exists.\\
\end{tabularx}}

\sect{04}{Deployment procedure and creation evidence}
\begin{enumerate}[label=\arabic*.,itemsep=1pt]
\item Publish the image above, then prepare Remix copies with \code{npm run remix:prepare}. Compile CPT and CampusMemo in web Remix: Solidity 0.8.24, OpenZeppelin 5.0.2, optimizer 200 runs, EVM paris; enable Generate contract metadata.
\item Select Remix VM and run \code{scripts/remix-test.js} for the full functional checks. Switch to Browser Extension / MetaMask, connect A on Sepolia, and keep transaction Value at zero.
\item Deploy CPT with \code{initialAdmin=A}: \tx{0xefd25c936046bf9a650159005dc661d5f8e1e485f2e0e2d9ea2fa9e6143169cc}{CPT creation transaction}. Each linked receipt identifies A as creator and T or N as the created contract.
\item Initial reads: \code{balanceOf(T)=totalSupply()=1000 CPT}, \code{WELCOME_POINTS()=5 CPT}; N links to T, costs 100 CPT per mint, caps supply at 10 and initially has no NFTs. The Sepolia checker \code{scripts/remix-sepolia-check.js} in \code{initial} mode confirms these values without sending transactions.
\end{enumerate}

\sect{06}{How to verify without changing the contracts}
{\small
\textbf{Historical evidence.} In T/N's Transactions tabs, match sender and function above, then inspect Logs. For \code{Transfer} logs, indexed topics 1/2 are from/to addresses: T stores the CPT amount in Data, whereas N stores the NFT ID in topic 3. Decode hex integers; divide CPT amounts by $10^{18}$. A burn uses the zero address as recipient; the NFT mint uses it as sender. Failed simulations and read-only calls do not create receipts. The administrator-burn function and rejected permission / cap cases are covered by source and VM tests, rather than this Sepolia demonstration sequence.

\textbf{Read-interface availability.} If source verification is pending, Etherscan shows bytecode without a verified Read Contract interface. Transaction inputs and logs remain public; decode them with the submitted contract ABI. After source verification, use Contract $\rightarrow$ Read Contract for the queries below. Alternatively compile the submitted source in Remix, load T/N using At Address, connect Sepolia, and perform only read calls. No administrator key is needed for reads.

\textbf{Final checks.} After exactly steps 1--15, \code{T.totalSupply()} and \code{T.balanceOf(T)} should each be 818 CPT; A/B/C each hold zero CPT. \code{T.isMember(B)=false}, \code{T.isMember(C)=true}, \code{N.totalMinted()=1}, \code{N.ownerOf(1)=B}, and \code{N.listings(1)} is cleared. Run \code{scripts/remix-sepolia-check.js} with the page-1 addresses, image URL and \code{stage: "after-demo"} for a read-only block snapshot. Use \code{inspect} if subsequent transactions changed the state.

\textbf{Metadata check.} Read \code{N.tokenURI(1)} and decode its Base64 JSON: name \code{Campus-Memo #1}, Edition 1, and the page-1 image URL. Ownership changes and membership withdrawal leave that URI unchanged. The complete URI for token 1 is reproduced below.
